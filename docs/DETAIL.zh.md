## 工作流程

```
⟳ 刷新（前端）
  → GET /radar-fetch?url=<RSS>   Host 端 Node 抓取（无 CORS，浏览器同源策略不适用）
  → 前端解析 RSS/Atom，与已入库条目按 URL/标题键去重，只取新条目
  → GET /radar-ai?payload=…      Host 端用 ctx.llm.stream 调用 DSH 默认模型
      （6 条/批 × 3 路并发；输出 keep/kind/category/obtain/quality/titleZh/noteZh/reason）
  → keep=false 丢弃；info 且 quality ≤ 1 的低质条目不入库
  → 其余带着中文翻译入库 → 频道分流展示
```

模型选择：优先 `agentDefaultModel.currentSelection()`（DSH 设置里的默认模型），否则取第一个已注册 provider 的第一个模型。「关于」页会显示实际使用的模型。

## 功能

- **兴趣频道**：真福利精选 / 全部白嫖 / 好价 / 开源 / 重要新闻 / 行业资讯 + ★ 收藏，频道名带实时计数。
- **AI 自动流水线**：keep 筛选（噪音/灌水/软文淘汰）→ 六类形态分流 → 27 类分类 × 6 级获取方式 × 1–5 星定级 → 标题/摘要翻译成中文 → 入库。news/info 有明确门槛：论坛闲聊、日常讨论、求助吐槽判 noise。
- **🔍 复审本栏**：对已入库旧条目按当前 AI 标准重跑筛选（★ 收藏不受影响），用于清理早期宽松标准入库的内容。
- **三级筛选**：内容形态 × 垂直分类 × 获取方式，收在「⚙ 过滤」弹层里（按钮显示已启用筛选数）。
- **屏蔽词防火墙**：命中屏蔽词的条目在列表中直接隐藏。
- **数据源管理**：内置精选源清单（可启停 / 删除），可编辑订阅地址、新增自定义 RSS 源、单独刷新某个源、7 源 3 路并行刷新。
- **条目操作**：☆ 收藏（「★ 收藏」频道聚合）、点击打开原文自动标记已读（置灰、排序沉底）、复制兑换码。
- **刷新状态胶囊**：工具栏右侧一枚小胶囊（刷新中显示进行中的源 / 完成摘要 / 失败警示），点击弹出最近 8 条刷新记录。
- **首次使用**：无数据时打开自动执行一轮刷新，完成后清除内置演示条目。

## 数据存放

- 持久化文件：`<DSH profile 目录>/resource-radar-data.json`（Host 端 `/radar-store` 路由读写），条目/收藏/屏蔽词/自定义源都在其中，可直接备份或迁移。
- `localStorage` 仅作缓存兜底（Host 路由不可用时仍可工作），以文件内容为准。

## 已知限制

- **Host 端更新需完整重启**：DSH 桌面宿主只在进程启动时加载 Host 半（`index.js` 的三个路由），改完 Host 代码要重启 DeepSeek Harness，前端部分刷新页面即可。
- **Cloudflare 防护站点**（LINUX DO、NodeSeek）：Node 直连返回 403「Just a moment」，需另行部署 FlareSolverr；这些源默认停用并在名称中标注。
- AI 定级依赖 DSH 中配置的模型，单次刷新的耗时与费用随新条目数线性增长；RSS 抓取上限每源 40 条。
- 不含定时自动刷新、推送路由与多用户。
